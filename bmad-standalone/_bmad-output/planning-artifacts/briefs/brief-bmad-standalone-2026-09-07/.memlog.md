- (note by user) Simple browser-based, single-player Tetris with arrow key controls, line clearing, score counter, increasing speed, game over screen
- (decision by user) Primary goal: High performance, smooth browser experience (target 60 FPS, lag-free)
- (decision by user) Selected path: Coaching path
- (decision) Purpose: not a real product — technical experiment comparing BMAD standalone (skill-file) flow vs LangGraph-integrated BMAD flow on an identical, fully-scoped small task. Tetris chosen for zero scope ambiguity. Brief is build-notes level; product-thinking sections (differentiation, market, growth) are out of place here.
- (decision) Audience: just the tester (user) plus a few people who might open the file in a browser. No real external user base.
- (decision) Definition of working: a full round (spawn -> play -> line clear -> game over -> restart) completes with no console errors; controls feel lag-free.
- (decision) v1 scope IN: arrow-key move/rotate, soft drop, hard drop, line clearing, score, level/speed ramp, pause/restart, next-piece preview, game-over screen.
- (decision) v1 scope OUT (deliberate): sound/music, mobile touch controls, localStorage high-score persistence, hold-piece, full SRS wall-kick rotation system, multiplayer.
- (decision) Technical constraints: zero dependencies, single HTML file, vanilla JS (ES2020+), Canvas 2D, no build tooling, must run offline via file://.
- (decision) Visual style preference (not a hard constraint): retro arcade/terminal feel, dark theme, monospace font, classic piece colors (I-cyan/O-yellow/T-purple/S-green/Z-red/J-blue/L-orange).
- (decision) Brief stays self-contained to the Tetris spec; the standalone-vs-LangGraph comparison methodology is out of scope for this document, referenced only as one-line context.
- (decision) Definition of Done is a manual smoke test only (open file, play a round, no console errors); no automated test suite expected.
